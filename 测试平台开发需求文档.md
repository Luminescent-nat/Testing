## 1. 项目概述

### 1.1 项目背景
开发一个测试平台，用于管理Android设备的测试任务，支持多用户并发使用，实现测试资源的统一管理和测试任务的自动化执行。

### 1.2 核心目标
- 支持多用户同时使用，设备权限隔离
- 灵活的测试项配置，用户自定义执行命令
- 支持多种执行类型（ADB命令、推送执行、本地执行）
- 实时测试进度展示和完整的测试报告
- 管理员完整的权限管理和审计能力

### 1.3 术语定义

| 术语 | 定义 |
|------|------|
| **测试模块** | 测试任务的分类单元，如DDR测试、EMMC测试 |
| **测试项** | 具体的测试执行单元，包含执行命令和参数 |
| **测试任务** | 一次测试执行的实例，包含选中的测试项列表 |
| **测试记录** | 单个测试项的执行结果和日志 |
| **执行引擎** | 负责实际执行测试命令的核心组件 |
| **测试工具** | 需要推送到设备执行的二进制文件 |

## 2. 系统架构

### 2.1 技术栈选型

| 层级 | 技术选型 | 说明 |
|------|---------|------|
| **前端** | Vue3 + Element Plus + Pinia | 现代化响应式UI框架 |
| **后端** | FastAPI (Python 3.10+) | 高性能异步Web框架 |
| **数据库** | PostgreSQL 15 | 关系型数据库，支持JSON字段 |
| **缓存** | Redis 7 | 会话缓存、任务队列、进度推送 |
| **任务队列** | Celery + Redis | 异步任务执行 |
| **ADB服务** | adb-python (pure-python-adb) | ADB设备管理和命令执行 |
| **文件存储** | 本地文件系统 | 测试工具和脚本存储 |

### 4.2 功能详细设计

#### 4.2.1 用户注册 (M01-F01)

**功能描述**: 新用户注册账号

**输入参数**:
```json
{
  "username": "string, 必填, 3-20字符, 字母数字下划线",
  "password": "string, 必填, 6-32字符",
  "pc_identifier": "string, 自动生成, PC的唯一标识"
}
```

**处理逻辑**:
1. 校验用户名唯一性
2. 密码使用bcrypt加密存储
3. 默认角色为"user"
4. 记录PC标识符（IP + MAC地址）

**输出结果**:
```json
{
  "code": 200,
  "message": "注册成功",
  "data": {
    "user_id": 123,
    "username": "testuser"
  }
}
```

**异常处理**:
- 用户名已存在: 返回400错误
- 参数校验失败: 返回422错误

#### 4.2.2 用户登录 (M01-F02)

**功能描述**: 用户登录获取访问令牌

**输入参数**:
```json
{
  "username": "string, 必填",
  "password": "string, 必填"
}
```

**处理逻辑**:
1. 验证用户名密码
2. 生成JWT Token（有效期24小时）
3. 更新最后登录时间和PC标识符
4. 记录登录日志

**输出结果**:
```json
{
  "code": 200,
  "message": "登录成功",
  "data": {
    "access_token": "eyJhbGciOiJIUzI1NiIs...",
    "token_type": "bearer",
    "expires_in": 86400,
    "user": {
      "id": 123,
      "username": "testuser",
      "role": "user",
      "email": "test@example.com"
    }
  }
}
```

#### 4.2.3 管理员用户管理 (M01-F05/F06)

**功能列表**:
- 分页查询用户列表（支持按用户名、角色、状态筛选）

### 7.4 结果解析规则

**解析配置说明**:

| 字段 | 说明 | 示例 |
|------|------|------|
| `pass_pattern` | 判断成功的正则表达式 | `"Test passed"` |
| `fail_pattern` | 判断失败的正则表达式 | `"Test failed|ERROR"` |
| `extract_pattern` | 提取关键数据的正则 | `"Score: ([\\d.]+)"` |
| `timeout` | 执行超时时间（秒） | `600` |

**解析逻辑**:
```python
def parse_result(output: str, config: dict) -> dict:
    result = {"status": "unknown", "data": {}}
    
    # 1. 检查失败
    if config.get("fail_pattern"):
        if re.search(config["fail_pattern"], output, re.IGNORECASE):
            result["status"] = "fail"
            result["fail_reason"] = extract_fail_reason(output)
            return result
    
    # 2. 检查成功
    if config.get("pass_pattern"):
        if re.search(config["pass_pattern"], output, re.IGNORECASE):
            result["status"] = "pass"
    else:
        # 默认返回码0为成功
        result["status"] = "pass"
    
    # 3. 提取数据
    if config.get("extract_pattern"):
        matches = re.findall(config["extract_pattern"], output)
        result["data"]["extracted_values"] = matches
    
    return result
```

### 8.4 并发控制

**并发策略**:
```python
# 设备锁机制
class DeviceLock:
    _locks = {}
    
    @classmethod
    async def acquire(cls, device_serial: str, task_id: int, timeout: int = 30):
        """获取设备锁"""
        if device_serial in cls._locks:
            raise DeviceBusyException(f"设备 {device_serial} 正被其他任务占用")
        
        cls._locks[device_serial] = {
            "task_id": task_id,
            "acquired_at": time.time()
        }
    
    @classmethod
    async def release(cls, device_serial: str):
        """释放设备锁"""
        if device_serial in cls._locks:
            del cls._locks[device_serial]
```

**超时机制**:
- 每个测试项可配置超时时间
- 任务整体超时（默认2小时）
- 设备锁自动释放（任务完成后）

### 10.3 数据字典

#### 用户角色 (role)
- `admin`: 超级管理员，拥有所有权限
- `user`: 普通用户，只能操作本机设备和查看个人记录

#### 设备状态 (status)
- `online`: 设备在线且空闲
- `offline`: 设备离线
- `testing`: 设备正在执行测试任务

#### 执行类型 (exec_type)
- `adb_shell`: ADB Shell命令执行
- `push_exec`: 推送文件后执行
- `host_exec`: 在PC端执行

#### 任务状态 (status)
- `pending`: 等待执行
- `running`: 执行中
- `completed`: 成功完成
- `failed`: 执行失败
- `cancelled`: 已取消

#### 记录状态 (status)
- `pending`: 等待执行
- `running`: 执行中
- `pass`: 测试通过
- `fail`: 测试失败
- `skip`: 已跳过（兼容性问题）
- `error`: 执行出错

### 11.8 错误码定义

| 错误码 | 描述 | 场景 |
|--------|------|------|
| 200 | 成功 | 请求成功 |
| 400 | 请求参数错误 | 参数校验失败 |
| 401 | 未授权 | Token缺失或过期 |
| 403 | 禁止访问 | 权限不足 |
| 404 | 资源不存在 | 请求的资源不存在 |
| 409 | 资源冲突 | 设备被占用、用户名已存在 |
| 422 | 语义错误 | 业务逻辑错误（如不兼容） |
| 500 | 服务器内部错误 | 系统异常 |

## 13. 非功能需求

### 13.1 性能需求

| 指标 | 目标值 | 说明 |
|------|-------|------|
| 页面加载时间 | < 2秒 | 首屏加载完成 |
| API响应时间 | < 200ms | 95%的请求 |
| 并发用户数 | ≥ 50 | 同时在线 |
| 并发任务数 | ≥ 10 | 同时执行测试 |
| 数据库查询 | < 100ms | 单表查询 |
| WebSocket延迟 | < 100ms | 消息推送延迟 |

### 13.2 安全需求

**认证安全**:
- JWT Token有效期24小时
- 支持Token刷新机制
- 密码使用bcrypt加密（cost factor: 12）
- 登录失败次数限制（5次/小时）

**数据传输安全**:
- 使用HTTPS协议
- API请求CSRF防护
- 敏感参数签名验证

**权限控制**:
- RBAC权限模型
- 接口级权限控制
- 数据级权限隔离（设备归属）

### 13.3 可用性需求

**可靠性**:
- 系统可用性 ≥ 99.5%
- 关键数据定期备份
- 支持服务降级

**容错性**:
- 设备断线自动检测
- 任务执行异常自动恢复
- WebSocket断线自动重连

**易用性**:
- 响应式布局（支持1366x768及以上分辨率）
- 操作反馈明确
- 错误提示友好

### 13.4 兼容性需求

**浏览器支持**:
- Chrome ≥ 90
- Firefox ≥ 88
- Edge ≥ 90
- Safari ≥ 14

**设备支持**:
- Android ≥ 8.0
- 支持ARM32/ARM64架构
- 支持主流设备厂商（Google、Samsung、Xiaomi等）

### 13.5 部署需求

**服务器配置**:
- CPU: 4核及以上
- 内存: 8GB及以上
- 磁盘: 100GB SSD（根据工具文件大小调整）
- 网络: 100Mbps，固定公网IP（可选）

**软件环境**:
- OS: Ubuntu 22.04 LTS / CentOS 8
- Python: 3.10+
- Node.js: 18+ (前端构建)
- ADB: Android Platform Tools
