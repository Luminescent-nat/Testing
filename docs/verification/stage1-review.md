## 2. 四维评审

| 维度 | 结论 | 说明 |
|---|---|---|
| 可扩展性 | 有风险 | 数据量×10时 SQLite 单写入者、报告同步聚合和单实例调度先成为瓶颈；设计保留分页、索引、异步报告和未来 PostgreSQL 路径，但没有当前负载测量。新增执行语义可限制在共享判定/聚合模块，新增 UI 状态可限制在组件层。 |
| 一致性 | 有风险 | 目标设计沿用 FastAPI/SQLAlchemy/Vue/Element Plus，不引入新语言；共享 owner、状态机和统计公式一致。但当前 legacy 错误结构、动作路径与目标不同，双轨期若各自实现会破坏一致性。 |
| 风险 | 有风险 | RSK-01～06已有应对；仍有单实例调度、SQLite 单点、存量owner为空、迁移回滚和唯一证据保护风险。当前无实机、Docker、完整Playwright和迁移证据，不得放行发布。 |
| 成本 | 通过 | 复用现有技术栈，不新增Celery/Redis或新UI框架；以下为基于任务拆分的人日估算而非实测承诺，当前新增基础设施费用按0元/月计，既有电脑和运行环境不重复计价。 |

## 4. 风险与整改项

| 编号 | 问题 | 严重度 | 建议动作 | 负责人/去向 |
|---|---|---|---|---|
| ARC-01 | 数据量×10瓶颈只有定性判断 | 中 | 阶段5在隔离副本做分页、统计和报告负载测量；不达标先加索引/异步化，再评估PostgreSQL，不把历史指标当门禁 | 后端开发+测试；接受并纳入阶段5 |
| ARC-02 | 单实例scheduler/SQLite不支持多副本并发 | 高 | 本轮部署明确仅一个后端调度实例；多副本需求出现时必须新ADR评审分布式锁/队列和数据库，不得直接水平扩容 | 后端开发+运维；接受当前约束 |
| ARC-03 | legacy与目标契约双轨漂移 | 高 | legacy只委托同一服务；前端切换后联调并移除适配，任何契约变更双方确认、版本+0.1 | 前后端开发；纳入各实施批次 |
| ARC-04 | 存量owner=null会阻断普通用户 | 高 | 上线前导出未分配清单，管理员逐台分配；禁止自动转给首个刷新用户 | 管理员+后端开发；R5/R6前置条件 |
| ARC-05 | 迁移和删除可能破坏历史证据 | 高 | 只在备份副本演练，核对行数/约束/完整性/哈希；任务采用软删除，archive逐项判断 | 后端开发+测试；阶段2/3门禁 |
| ARC-06 | token已确认，但新组件/页面规格未经确认且页面证据缺失 | 中 | 组件/页面四表契约和六段规格已形成评审稿；用户确认后才实施，并实际走查九状态、四边界态和断点键盘 | 前端开发+用户确认；T-22～T-35阻塞 |
| ARC-07 | 当前无ADB设备、Docker和完整浏览器证据 | 高 | 对应条目标无法核验/未执行；设备接入和隔离环境具备后补跑，不得签整体验收 | 测试+运维；保留到阶段5 |

## 6. 最终结论与交接门禁

**最终结论：有条件通过。** 依据是四维均完成审查，成本有估算，风险均有责任角色和去向；但“有条件通过”不等于开始编码的无条件许可。

进入对应实现前必须同时满足：

1. 后端接口/状态契约、ADR 和 UI token 已于 2026-11-12 确认；实现不得擅自改变口径。
2. 新增组件/页面四表契约和六段规格已形成评审稿；须经用户确认后才可启动 T-22～T-34，T-35 仍等待全部前端任务。
3. ARC-02～05作为相关批次的强制验收条件落实；ARC-01纳入最终回归，ARC-06～07保持阻塞至证据具备。
4. 每批先写能复现缺陷的正常/边界/异常测试，再改实现，保存原始运行结果。

当前交接结论：**后端、基础设施及UPFM分包和前端T-20/T-21分包可按依赖放行；共享组件/页面实现分包不放行。** 详细产出物与依据核对见[阶段1交接单](stage1-handoff.md)。本结论只允许开发委派，不代表任何业务任务已完成或验收通过。
