## 4. 演示前必须修复/收口项

### D-01（P1，必修）：任务监控页测试项名称字段错误

- 位置：`frontend/src/views/tasks/monitor.vue:160,193,432,510` 使用 `item.name`；契约与后端 TestRecord 字段为 `item_name`。
- 实测表现：执行流程/执行详情的测试项名称缺失，日志标题出现 `=== DDR / undefined ===`。
- 修复：统一使用 `item_name`，或仅在 API 归一化层显式映射；WebSocket `current_item/completed_results` 与 REST 记录必须走同一字段口径。
- 配套测试：记录含 `item_name`、旧 `name` 不得作为契约字段依赖；真实浏览器断言测试项名称可见且页面/日志无 `undefined`。

### D-02（P1，必修）：全新空库报告页产生 404 控制台错误

- 位置：`reports/index.vue:515-521` 页面挂载即调用 `GET /reports/summary/all`；`reports.py:404-405` 对零任务抛 404。
- 实测表现：空态“暂无报告”能够显示，但浏览器控制台出现 404；有报告后同一页面无错误。
- 推荐修复：该“全部任务汇总”读接口在零任务时返回 200 + 空汇总（`tasks=[]`、`results=[]`、五类计数为 0、`pass_rate=null`），与统计读模型的零数据口径一致；不得把空数据当作不存在资源。
- 配套测试：后端空库/有数据两组；前端空态、零分母 null、有数据三组；浏览器 console 0 error。

### D-03（P1，必修）：报告 E2E 用例不能作为有效验收证据

- 位置：`frontend/tests/e2e/task-workflow.spec.js:50-66`。
- 问题：使用 `item_ids=[]` 创建任务，当前契约必然 400；代码却允许失败后继续；空报告页选择器仍等待不存在的 `.reports-page/.report-list/.el-card`。
- 修复：空报告态与有报告态拆成两个用例；有报告态使用合法、已完成的真实 fixture，不再静默接受任务创建失败；选择器使用当前稳定结构或专用测试标识。
- 验收：Playwright 全部通过，且报告用例确实断言非空报告、时间、五类计数和详情，而不是只证明空页面能打开。

### D-04（演示启动策略，必须确认）：默认历史库不能直接启动

- 实测：既有 `test_platform.db` 无 `alembic_version`，结构存在 12 类差异；隔离副本启动被 `database.py:294-298` 拒绝。
- **本轮推荐**：保留历史库不动，演示使用显式的新库 `demo.db` 与独立 `storage/demo`，由 Alembic 自动初始化；提供明确的 `start_demo` 配置/脚本，避免误用历史库。
- 若演示必须保留历史任务、账号和知识数据，则不能用新库规避，必须另行实施历史库备份、结构对账、迁移与回滚演练；这不再是“小收尾”。

### D-05（P1，范围收口）：每日定时不得作为可用演示功能

- 任务板 T-11/T-12 未实施，但 `tasks/create.vue:123-127` 已暴露“每日定时”选项。
- 演示版二选一：隐藏/禁用 daily 并标注“后续版本”，或完成 daily 契约实施与并发/跨天/重启测试。推荐前者，避免扩大本轮范围。
- 立即执行已经实测；once 若纳入演示，需单独做一次到点触发与重启恢复验证。

## 5. AI 配置口与后续模块边界（本轮只做预留，不开发新 AI 模块）

### 5.1 本轮需要补齐的配置说明

现有后端已经支持以下环境变量：`LLM_API_KEY`、`LLM_BASE_URL`、`LLM_MODEL`、`LLM_TIMEOUT`、`LLM_TEMPERATURE`、`LLM_MAX_TOKENS`，客户端为 **OpenAI 兼容 `/chat/completions`** 协议。`.env.example` 当前未列出这些配置，需补齐注释与示例（密钥留空，不写真实密钥）。

演示约定：

- 不填 `LLM_API_KEY`：允许启动；自然语言创建使用规则规划；不得声称使用了 AI。
- 填写后：仍须经过设备授权，授权失败时知识/LLM 调用计数为零（v1.1 已验证）。
- 密钥只在后端环境变量中，不进入前端、日志、报告或 Git。
- `LLM_PROVIDER` 目前不是通用多供应商路由，演示文档只能承诺“OpenAI 兼容接口”，不能夸大为任意模型供应商均已适配。

### 5.2 后续 AI/Skills 模块接入原则

1. 保持三个能力边界：任务规划、测试用例草案生成、结果判定；分别使用结构化输入/输出与超时/异常处理。
2. Skills 生成的测试用例只能作为**待校验草案**，必须复用现有模块/测试项 Schema、参数校验和 manifest 工具声明，不得直接写库或绕开评审。
3. AI 判定继续失败关闭：结构非法、超时、无有效结论均为 error，不得默认 pass；保留 evidence、model、prompt/schema 版本供审计。
4. 后续模块不得改变本轮已确认的授权顺序与统一任务创建服务；新增接口须另走契约评审与版本变更。
5. 本轮只保留配置口与上述边界，不把“未来可接入”写成“AI 功能已经验收”。
