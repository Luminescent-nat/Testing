# 开发自测与独立验收规则

- 版本：v1.0
- 日期：2026-11-12
- 适用：后续所有开发任务与 R1～R31 最终验收
- 原则：实际运行、证据可复核、异常路径必测、未执行不算通过

## 1. 通用证据门禁

每项验证记录：任务编号、commit/变更集、环境、命令、开始/结束时间、退出码、完整 stdout/stderr、测试数据准备和实际结果。失败日志必须保留，修复后追加新日志，不覆盖失败证据。

禁止：只看代码声称通过、只测正常路径、删除或放宽断言、把 500 当可接受、把跳过写成通过、用 Mock 结果冒充实机、用历史截图代替当前页面。

所有测试使用独立临时数据库与 storage。E2E 必须设置 `E2E_TEST_MODE=1`、`DATABASE_URL=E2E_DATABASE_URL`，且不得使用平台默认数据库。回归前后复核受保护数据库、备份、上传、报告、日志和 archive 哈希。

## 2. 后端基础回归

在 `test-platform/backend/` 执行：

```bash
python -m pytest tests -q -W error::pytest.PytestUnraisableExceptionWarning
```

通过标准：退出码 0，收集数不少于变更前基线，新增测试全部执行，0 failed、0 warning；不得出现汇总后线程/子进程异常。当前参考基线为 189 个既有用例，但新增实现必须增加覆盖，不能以仍为 189 作为充分条件。

## 3. 接口四类强制校验

### 3.1 幂等与只读

| 方法/场景 | 动作 | 通过标准 |
|---|---|---|
| GET | 在数据不变时连续请求 2 次 | 响应一致，无副作用 |
| POST 任务/重跑 | 同用户、同 Idempotency-Key、同请求体重放 2 次 | 返回首次响应，只创建一个任务/执行实例 |
| 同键不同请求体 | 重放修改后的请求体 | 409 CONFLICT，无新增 |
| daily | 同 template_id+scheduled_for 并发扫描 10 次 | 恰好一个实例，只启动一次 |
| PATCH | 同载荷重放 2 次 | 与一次更新的业务状态一致；版本冲突按契约处理 |
| 取消/禁用/软删除 | 重复执行 2 次 | 第二次不 500，不重复杀进程/删记录，结果一致 |
| 批量导出 | 重复请求同一任务集 | 不修改业务记录，不静默跳过无权限任务 |

### 3.2 并发安全

对同一资源并发发出 10 个写请求，核对最终数据库、任务数和副作用：

- 同名用户创建至多一行；首管理员并发初始化至多一个 admin。
- 设备不同目标改派使用版本条件更新，旧版本不得覆盖新版本。
- 同幂等键任务创建至多一行；不同合法任务不得被错误去重。
- 最后一个 active 管理员不得被并发禁用/降级。
- 同一设备执行与排队交错时不双持锁、不旧任务释放新锁、不批量误 offline。

通过标准：无脏写、无 500、唯一约束正确、最终计数准确、日志无未处理异常。无法执行并发工具时只能在报告中注明降级为串行重放，该项不得声称完成并发验证。

### 3.3 输入校验

对契约每个字段分别构造四组：错类型、越界、超长、空值；可空字段的合法 null 不得误拒。数组另测重复、空数组和超上限，对象另测嵌套对象/数组/null。

重点样例：

- item_ids：`[]`、重复、0/负数、不存在、字符串。
- custom_parameters：未选 item_id、未知参数名、嵌套对象、数组、null、NUL/换行、shell 控制符。
- 合法保留：`0`、`false`、`""`、合法 http/https URL（含查询 `?&=`）。
- daily：`24:00`、`9:60`、空串、错类型；once：过去时间和非法格式。
- conditional_rules：list/标量根、空 conditions、未知操作符、非法正则、缺失 source/target、approx_ratio 目标 0。

通过标准：全部在任何业务写入前返回契约 HTTP 状态和 `{"code","message","details"}`；details 指向字段路径，无堆栈/SQL/绝对路径；数据库无新增或部分更新。

### 3.4 错误路径

每个端点适用的错误码至少真实触发一次，核对 HTTP、机器码、message、details。标记“不使用”的 NOT_FOUND 等条目记“不适用+契约理由”，不得为了覆盖率伪造错误；新增无法触发的适用错误码记“未验证”，总体不放行。

## 4. 核心状态与统计场景

| ID | 输入/操作 | 必须结果 |
|---|---|---|
| EXEC-01 | 非零退出，同时出现 pass_pattern 或 SKIP | fail，不得 pass/skip |
| EXEC-02 | rc=0、pass_pattern 未命中 | fail |
| EXEC-03 | pass/fail 同时命中 | fail |
| EXEC-04 | 无配置、空规则、未知操作符、AI无有效结论 | error，不得 pass |
| EXEC-05 | 超时、子进程启动异常 | timeout/error 分类准确 |
| SKIP-01 | rc=0，独立行 `RESULT: SKIP: 原因` | 原生 skip，原因贯通DB/WS/API/报告/前端 |
| SKIP-02 | `foo RESULT: SKIP`、`RESULT: SKIPPED` | 不误判 skip |
| STOP-01 | 5项中第2项 stop+fail | 3～5不执行且补skip，completed/failed、100%、50.0% |
| STOP-02 | 首项 stop+fail，其余4项skip | pass_rate=0.0，不是 null |
| STAT-01 | pass2/fail1/timeout1/skip2 | C=6、100%、50.0% |
| STAT-02 | 全skip或零有效分母 | result/pass_rate=null，显示无有效结果 |
| STAT-03 | 一项running，其余pass | running不计完成，任务不得completed |
| DASH-01 | passed/failed/全skip/running/failed/cancelled/零记录混合 | 仅completed且有效result进入分母，其余分列 |
| ZERO-01 | 耗时0、提取值0、无对应项、重名不同ID | 0显示0，按item_id对齐，无对应项标不可对比 |

每个场景至少覆盖服务层、API/WS和报告三层；前端另做实际渲染断言。

## 5. 调度、取消与恢复

- 两个连续计划时刻产生不同任务 ID、记录和报告，历史实例不变。
- 前一实例 running 时新实例 pending；设备锁按 FIFO，无双执行。
- 重启和跨天恢复至多触发最近一次计划一次，不逐日补跑。
- 未到期 once/daily 不被启动恢复误标 failed；非法时间在写前 400。
- pending/running 删除返回 409；终态软删除幂等，记录/报告引用一致。
- 取消后无 running 记录、无残留子进程，旧收尾不得把 cancelled 覆盖成 completed。

## 6. 数据库与部署验证

### 迁移

在新装空库和存量备份副本分别执行升级，记录 Alembic 版本、表结构、任务/记录行数、外键/唯一约束和 `integrity_check`。写非法外键与重复唯一键必须失败。执行回滚后恢复原结构和数据；异常中断不得静默删记录。没有实际回滚日志则 R20 不通过。

### Docker/工具/密钥

从干净上下文构建并启动，检查 manifest 声明的 runner、二进制和架构均可发现。合法 SECRET_KEY 可启动；空、短于32、常见占位和 Compose 示例值必须启动失败且日志不打印密钥。缺失范围内 APK/外设按 R3 skip，不伪造输出。构建、启动、工具发现和弱密钥拒绝均保存原始日志。

## 7. 前端与浏览器验证

在 `test-platform/frontend/` 执行 `npm test`、`npm run lint`、`npm run build` 和隔离 Playwright。交付门槛：

- Vitest 退出码 0，新增组件/工具正常、边界、异常用例通过。
- lint 0 error、0 warning；不得通过关闭规则或排除问题文件达标。
- build 退出码 0，无 CJS、Sass legacy API 和大 chunk 警告。
- 浏览器 console 0 error、0 warning，无失败请求或未处理 Promise。
- 最终交付不得残留未标注 mock；mock 只能来自 mock-api 按确认契约生成的文件。

### 页面通用矩阵

实施前核对[共享组件契约](../contracts/frontend-components-v1.0-review.md)、[页面契约](../contracts/frontend-pages-v1.0-review.md)及 `docs/design/components/`、`docs/design/pages/` 对应六段规格的状态。当前这些新增文档为评审稿，未经用户确认不得启动 T-22～T-34；确认后若表格或规格变更，须同步更新受影响任务和测试矩阵。

每个路由页面（登录、仪表盘、设备、模块、AI、任务列表/创建/监控、报告、记忆体、知识库、用户、个人信息、404）实际触发 loading/empty/error/超长数据。空态和错误态不得省略，超长文本/表格不得造成页面横向滚动，禁用和只读不得触发写请求。

共享组件逐一触发 default/hover/active/focus/disabled/loading/empty/error/readonly，并保存状态矩阵；写“不适用”必须有组件语义理由并经验收方核对。

### 响应式与可访问性

- 亮暗主题均在 360、767、768、1024、1025、1440px 截图，覆盖 <768、768～1024、>1024 三档。
- 对齐偏差 >1px、间距非4倍数、裸颜色/字号/阴影均记问题并附修复建议。
- 正文实测 ≥4.5:1，大字/控件/焦点 ≥3:1；禁止目测，透明度叠加后的实际颜色也要测。
- 检查 Tab 顺序、可见焦点、Enter/Space、Escape、焦点圈定与返回、无键盘陷阱、200% 缩放和 reduced-motion。
- 状态不能只靠颜色表达，aria 名称/角色/实时区域符合组件规格。

### WS 与交互资源

监控页连续进出 5 次，比较 WS 连接数、重连 timer、日志监听器和子进程/请求：卸载后全部清理，无重复日志、无多余连接。首屏不得自动 ADB 扫描，只有明确刷新操作触发发现。认证失败、任务结束和卸载均停止重连。

## 8. UPFM 与实机证据

静态核对 T1-01～27、6+4+2+4+5+6 和38条源用例映射，检查缺失、重复和 T2～T4 混入。画像期望值记录来源、容差和适用板型，自身实测值只能标回归基线。

实机报告记录 `adb devices -l`、commit、serial、板型、环境、只读操作清单、静态覆盖、实机覆盖和逐项 skip 原因。外设/APK/烧录/重启/人工项不得强行执行或改判 pass。当前无设备时 R3 为“无法核验”，整体验收不通过。

## 9. 最终验收判定

1. 验收方独立核对任务 DoD 与证据，抽查至少全部 P0 场景、每个写接口重放/异常和关键页面。
2. 按 R1～R31 逐条填“通过/不通过/无法核验”，每条链接当前原始证据。
3. 任一不通过或无法核验，总体为“验收不通过”；整改后重新执行受影响测试及全量回归。
4. 只有全部范围内条目有当前通过证据，才可提交用户签署验收通过。
