# ADR-001：采用契约先行的演进式整改

- 状态：accepted
- 日期：2026-11-09

## 背景

R1～R31 要求保留 v2.3+T1 范围，同时修复权限、执行、调度、统计、迁移和 UI 缺陷；R20、R29、R30 要求保留历史数据并形成可追溯证据。现有平台已有可运行模块与回归基础，不能将审计发现等同于必须重写。

## 决策

采用契约先行、增量 schema、按语义分批的演进式整改。

- 复用 FastAPI、SQLAlchemy、Vue 3 与现有测试体系。
- 每批只处理一个语义主题并保留独立回归证据。
- 先完成测试隔离与数据备份，再改业务实现。
- 契约、ADR 和架构评审是实施门禁。

## 备选方案

- 方案 A：推倒重写 — 否决；实现成本、运维成本和集中迁移风险评分均为 1。
- 方案 B：最简局部补丁 — 否决；可扩展性、一致性和风险可控性评分均为 1。
- 方案 C：契约先行增量整改 — 采纳；权衡矩阵总分 23，能保留现有资产并统一语义。

## 后果

正面影响：降低迁移和回归风险，缺陷可按批次验证。负面影响：需要维护新旧契约过渡与额外文档。跟进项：每批必须记录兼容路径、回退和实际测试证据，禁止以计划替代验收。
