# ADR-003：任务创建采用原子参数契约与幂等边界

- 状态：accepted
- 日期：2026-11-09

## 背景

R13、R14 要求 `custom_parameters` 按测试项 ID 分组并在任何业务写入前拒绝非法选择；R16、R17 又要求调度触发不重复。当前创建与执行对参数结构的解释不一致，分散校验会产生部分写入。

## 决策

把一次任务创建定义为一个原子契约：先完整校验设备授权、item_ids、嵌套标量参数和调度时间，再在单事务中写入。

- 参数结构固定为 `{item_id字符串:{参数名:标量}}`，保留 0、false 和空串。
- 未选中的参数键、重复/空 item_ids 及非法值均在写入前拒绝并返回字段路径。
- 客户端重试使用用户范围内唯一的 `Idempotency-Key`，相同请求返回原任务，不同请求体复用键返回 409。
- 调度实例的计划时刻唯一约束由 ADR-004 进一步约束。

## 备选方案

- 方案 A：另建任务编排服务 — 否决；本轮无独立服务需求，增加成本。
- 方案 B：执行器运行时容错非法参数 — 否决；违反写前校验并可能产生无效任务。
- 方案 C：统一 API 校验、单事务和幂等键 — 采纳；与现有 FastAPI/SQLAlchemy 同族且可测试。

## 后果

正面影响：创建与执行结构一致，重试不会重复建单。负面影响：需增加幂等记录和请求摘要存储。跟进项：覆盖四组非法字段、重放对比、并发 10 写及实际落库检查。
