# ADR-004：daily 模板与独立执行实例分离

- 状态：accepted
- 日期：2026-11-09

## 背景

R16、R17 要求 daily 持续触发、每次执行有独立历史并对同一计划时刻幂等；R19 要求重启恢复不影响未到期任务。复用同一个 pending 任务会在首次完成后停止触发并混淆历史。

## 决策

daily 任务作为长期模板，每个计划时刻创建独立执行实例，以 `(template_id, scheduled_for)` 唯一约束去重。

- 实例拥有独立任务 ID、记录、日志与报告。
- 设备占用时新实例保持 pending，由设备锁排队。
- 恢复时当前计划时刻至多触发一次，不逐日补跑错过日期。
- 模板编辑不反写历史实例；历史无快照标记 legacy，不伪造。

## 备选方案

- 方案 A：重写为 Celery/Redis 调度平台 — 否决；当前单实例部署不需要新增基础设施。
- 方案 B：继续复用任务并重置状态 — 否决；覆盖历史且无法可靠区分计划时刻。
- 方案 C：现有调度器增加模板/实例和唯一约束 — 采纳；以最小增量满足独立历史与幂等。

## 后果

正面影响：历史不可变且重启安全。负面影响：数据模型和列表需区分模板与实例。跟进项：并发扫描 10 次、跨天恢复、前次仍运行和非法时间测试是必过门禁。
