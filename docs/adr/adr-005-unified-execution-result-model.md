# ADR-005：统一执行状态、业务结果和统计模型

- 状态：accepted
- 日期：2026-11-09

## 背景

R8～R12、R15、R31 要求失败关闭、原生 SKIP、五类终态、任务 status/result 分离以及统一进度和通过率。当前判定、WS、Dashboard 和报告分别计算，已产生假通过与统计失真。

## 决策

建立单一执行结果模型，所有消费端只读取统一记录终态和任务聚合结果。

- 非零退出优先 fail，独立行原生 SKIP 仅在 rc=0 时生效，缺有效判定配置不得 pass。
- stop-on-failure 给剩余项补带原因 skip，不执行命令或重试。
- `completed` 必须满足所有选中项均有终态且无 running；业务结果单独存 `result`。
- 通过率排除 skip，分母为零返回 null；Dashboard 仅统计 completed 且 result 有效的任务。

## 备选方案

- 方案 A：重写执行与报告引擎 — 否决；现有模块可复用，重写扩大风险。
- 方案 B：各页面自行修正显示 — 否决；不能解决落库和导出错误。
- 方案 C：统一服务端判定和聚合函数 — 采纳；一次定义供 WS、API、报告和前端复用。

## 后果

正面影响：消除 completed 等于 passed 等歧义。负面影响：需修正多处消费者并处理历史记录展示。跟进项：建立真值表测试，历史数据不得无依据批量重分类。
