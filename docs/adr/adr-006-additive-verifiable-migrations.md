# ADR-006：采用增量且可验证回滚的数据迁移

- 状态：accepted
- 日期：2026-11-09

## 背景

R20 要求存量数据保留、外键与唯一约束生效、回滚可验证；R29 禁止将数据库和备份当缓存清理。当前 create_all、stamp 与旧库升级路径未形成闭环。

## 决策

使用 Alembic 增量迁移和备份副本演练，不在启动时静默重建或删表。

- 新装库与存量库分别验证到同一 head。
- 新字段优先可空或有明确默认值，历史缺快照标 legacy。
- SQLite 每连接启用 foreign_keys，并用事务重建必要约束。
- 回滚前后核对表结构、任务/记录行数、约束与 SHA-256 证据。

## 备选方案

- 方案 A：重新设计并迁移到 PostgreSQL — 否决；本轮无该部署需求，增加运维成本。
- 方案 B：继续使用 create_all 或提示用户删库 — 否决；无法升级旧约束且有数据丢失风险。
- 方案 C：保留 SQLite 并补 Alembic 增量迁移 — 采纳；与现有栈一致且可在副本验证。

## 后果

正面影响：升级路径可审计，历史数据受保护。负面影响：SQLite 约束迁移需要表重建脚本和较长测试。跟进项：实际执行升级、非法写入、回滚与异常中断测试后方可签核。
