# ADR-007：测试与报告证据采用受保护生命周期

- 状态：accepted
- 日期：2026-11-09

## 背景

R3、R19、R29、R30 要求区分静态与实机证据、保持任务删除引用一致，并保护唯一数据库、日志、报告、上传和 UPFM 记录。历史测试写真实 storage 已造成产物混合风险。

## 决策

将可重建测试产物与唯一业务证据分生命周期管理，默认隔离而非默认删除。

- 每次测试使用独立数据库和 storage，E2E 必须显式指向隔离环境。
- 报告记录 commit、设备、板型、环境、Mock/实机类型和跳过原因。
- 删除任务前检查状态、授权及文件引用，禁止留下孤儿或误删共享证据。
- 文件清理依次执行引用检查、分类、哈希/备份、隔离、回归和确认删除。

## 备选方案

- 方案 A：重写为独立证据平台 — 否决；超出当前范围且成本高。
- 方案 B：每轮测试后清空 storage/archive — 否决；可能删除唯一实机证据。
- 方案 C：现有存储增加隔离、元数据和受保护清理流程 — 采纳；满足追溯且保留现有资产。

## 后果

正面影响：测试结果可复核且历史证据可恢复。负面影响：需维护元数据、哈希清单和保留策略。跟进项：完整 Playwright 正向流程与真实部署仍需独立证据，不能用隔离单元测试替代。
