# 后续开发委派实施方案

- 版本：v1.0
- 日期：2026-11-12
- 上游：R1～R31、接口契约 v1.0、ADR-001～008、双主题 token v1.0
- 用途：交由开发人员按任务包实施；本文件不记录任何新实现或测试结果

## 1. 实施目标与边界

在保留 FastAPI、SQLAlchemy、SQLite、Vue 3、Element Plus 和现有资产的前提下，修复设备授权、失败关闭、原生 SKIP、任务终态、daily、参数、统计、部署和前端闭环。不得推倒重写，不得把静态 UPFM 覆盖写成实机通过，不得删除唯一数据库、报告、日志、上传或 archive 证据。

非目标：本轮不引入 Celery/Redis、不迁移 PostgreSQL、不更换 UI 框架、不扩展到 UPFM T2～T4、不执行已排除的外设/APK/烧录/重启/人工项。

## 3. 分批与依赖

### 批次 G：共享基础先行

- T01 统一错误与目标路由适配。
- T02 Alembic、外键和迁移验证基础。
- T17/T18/T19 可并行的部署与命令安全基础。
- T20 前端契约客户端和 mock、T21 token 映射可与后端并行，后端未就绪时不得直连真实环境伪造成功。

### 批次 A：设备与资源授权

T03→T04→T05，T34 在 T03/T20/T22 后实施。所有手动、AI、报告和 WS 入口必须调用同一授权策略，不能只隐藏按钮。

### 批次 B：执行、终态与统计

T06→T07→T08；T15 可在 T06 后并行。统计读模型必须等待状态枚举和任务聚合稳定，禁止前端自行发明另一套公式。

### 批次 C：参数、调度、锁与生命周期

T09→T10；T11 与 T13 可并行，T12 等两者；T14 等 T07/T12/T13，避免与调度恢复实现并行修改同一逻辑。T09 与 T04 串行，避免 tasks.py 冲突。daily 的唯一约束和并发恢复测试是合并门禁。

### 批次 D：账号、前端与工程化

T16 与前端 T20/T21 可并行。T22 及所有共享组件使用新组件契约/规格，**这些新文档须经用户确认后才可实施**。T23～T34 按任务依赖实施，T35 最后治理 lint/build 警告，不能用删测试、关规则或隐藏 console 的方式伪造零警告。

### 批次 E：UPFM、文档与最终验收

T36 在判定和工具链稳定后执行；T37 汇总真实状态；T38 由验收方独立执行。当前无 ADB 设备时，实机项保持“无法核验”，整体验收不得签通过。

## 4. 并行规则与冲突控制

| 可并行工作 | 条件 |
|---|---|
| T03、T06、T16、T17、T19、T20、T21 | 不同模块；均只依据已确认契约/token |
| T09 与 T11 | T09 不修改 scheduler/models 的 daily 部分 |
| 前端页面任务 | 共享 API/client、组件和 token 已稳定；不得并行改同一文件 |
| 后端与前端 | 使用同一契约版本；前端使用 mock-api 生成物 |

同一文件只能有一个进行中的任务。发现未标依赖立即暂停并更新任务板，禁止口头约定。每个任务形成独立变更集，回退该变更集不得要求回退其他已完成任务。

## 5. 开发交付要求

每个任务必须提交：

1. 任务编号、实际改动文件和对应 R/契约/ADR。
2. 正常、边界、异常测试；写操作核对实际落库，幂等和并发按验证规则执行。
3. 原始命令、退出码、完整日志和测试清单，不能只贴“通过”摘要。
4. 四边界态或九状态的页面证据（仅涉及前端时），亮暗主题和断点证据按规则保存。
5. 回退说明、遗留问题和未验证项；不得把未执行写成不适用。
6. 更新任务板状态。只有 DoD 全部有证据才可标“已完成”，否则保持“进行中”或“阻塞”。

证据目录建议：`docs/verification/tasks/T-<n>/`，保存 `result.md`、原始日志、响应样例、数据库核对和截图索引。证据文件不能写入真实业务 storage。

## 6. 验收职责划分

- 开发人员：按任务自测、修正缺陷、提供完整证据，不得自行签最终验收。
- 验收方：核对契约版本与变更集，独立重跑关键测试和异常路径，抽查落库、重放、并发、报告和浏览器实际行为。
- 用户：确认新组件契约/规格、任何契约变更，以及最终验收报告。

最终按 R1～R31 逐条给出“通过/不通过/无法核验”。任一范围内不通过或无法核验，总体结论均为验收不通过；历史 189 passed 只作回归基线，不能替代新契约验收。
